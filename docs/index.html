Défense en profondeur

Cinq moteurs. Une seule stratégie.

Chaque famille possède une responsabilité claire. Les primitives communes restent partagées pour éviter les doublons et les compteurs concurrents.

Lancer FoxSecura localement

Le dépôt épingle ses versions principales pour garder un environnement reproductible. Activez aussi Server Members Intent dans le Discord Developer Portal.

git clone https://github.com/FoxSecura/FoxSecura.git
cd FoxSecura
export DISCORD_TOKEN="votre_token"
cargo check
cargo test
cargo run

OpenAI · omni-moderation-latest

AI Moderation utilise exclusivement le endpoint Moderations d'OpenAI. Le provider classe le contenu mais ne peut jamais appliquer directement une sanction Discord.

export OPENAI_API_KEY="votre_cle_api"
# endpoint: https://api.openai.com/v1/moderations
# model: omni-moderation-latest

SQLite

La base utilise rusqlite avec SQLite embarqué, WAL, migrations versionnées et repositories séparés de la logique Discord.

i18n · EN / FR / DE

Le catalogue Rust centralise les textes et vérifie que chaque clé possède une traduction non vide dans les trois langues.

Modèle de sécurité

Les détecteurs classent, les politiques prennent les décisions et la couche action applique. Cette séparation empêche un provider IA de sanctionner directement un membre.

État du projet

Des moteurs solides, une intégration en cours.

Les moteurs de protection et leurs tests sont présents. Le branchement complet aux événements Discord, à la configuration persistante et aux actions reste la prochaine grande étape.

FoxSecura est-il prêt pour la production ?

Les moteurs sont testés, mais l'intégration complète des protections aux événements et à la configuration serveur est encore en cours.

Pourquoi seulement trois commandes ?

FoxSecura privilégie un tableau de bord interactif pour éviter une liste de commandes difficile à maintenir.

L'IA peut-elle sanctionner directement ?

Non. OpenAI classe le contenu. FoxSecura décide ensuite selon sa policy et sa configuration.
